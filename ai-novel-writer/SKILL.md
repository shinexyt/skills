# AI 长篇小说创作：把用户带到可写状态

**职责边界**：本技能的**创作引导**只做三件事——① 把用户创意整理成小说设定；② 生成叙事蓝图并请用户确认；③ 规划章节路线。**阶段 2 完成后引导任务即结束**。之后的写作由 agent 自主进行：自己决定读哪些文件、怎么组织上下文、何时审阅与修订，不套用固定流水线。（另有一个只读的本地阅读器，见「阅读器」一节，不属于创作流程。）

## 工作区布局

```
<工作区>/
├── project.json     # 小说设定（六要素 + 目标章节数）
├── blueprint.json   # 叙事蓝图（人物/伏笔/时间线，稳定 ID）
├── outline.json     # 章节路线
├── state.json       # 可选：一致性备忘（人物现状/伏笔进展/时间线）
├── chapters/        # 正文：001.md, 002.md, ...
└── viewer.html      # 可选：本地阅读器（由 build_viewer.py 生成）
```

## 阶段 0：确认设定

与用户确认：标题、前提（一句话创意）、题材、叙事结构、视角、文风、目标章节数。信息不足时主动给出 2–3 个候选方案请用户挑选，不要反复追问细节。

- 有 `scripts/novel_tools.py` 时运行 `init <工作区> --title ... --premise ... --genre ... --structure ... --pov ... --style ... --chapters N` 生成 project.json；
- 没有脚本时直接写 project.json。

## 阶段 1：蓝图（必须请用户确认）

1. 生成 `blueprint.json`：主题、核心冲突、主角弧、节拍，以及人物 3–50、伏笔 3–50、时间线 6–200，全部带稳定 ID（`^[A-Za-z0-9][A-Za-z0-9_-]{0,79}$`，一旦创建终身复用）。字段与限制见 `references/schemas.md`。
2. 建议用 `validate <文件> --type blueprint` 校验；失败时做一次契约修复——只修格式与契约字段，缺事实依据的条目整条删除，不补 null、不编内容。
3. 用简洁中文向用户呈现蓝图要点（主题 / 核心冲突 / 主角弧 / 节拍 / 人物与伏笔清单），请用户确认。有意见就改到满意，**确认后才进入阶段 2**。

## 阶段 2：章节路线

1. 生成 `outline.json`：恰好 N 章、sequence 从 1 连续递增，每章含 title、sceneGoal（可观察的戏剧行动）、summaryTarget（本章结束时必须成立的新事实）、requiredStateIds（只能引用蓝图稳定 ID）。
2. 章与章要因果推进：每章承接前章后果并制造下一章条件；覆盖主角弧、伏笔埋设与回收、冲突升级、高潮与余波；相邻章节职责不重复。
3. 用 `validate <文件> --type outline` 校验后写入，并把路线摘要呈现给用户。

## 阶段 3：之后交给 agent

阶段 2 完成，本技能的引导职责结束。写作方式由 agent 自主决定，只需遵守 `references/writing-guide.md` 的静态规则。以下做法只是建议，按实际情况取舍：

- 写某一章前，**按需读取**工作区文件：outline.json 的本章与全书路线、blueprint.json、state.json、以及需要核对的具体已有章节（`chapters/` 下直接读，不必预先做上下文裁剪或摘要化）。
- 一章写完先按审阅清单自检；有硬伤就改，偏好类问题自行取舍。修订只针对问题处，不引入无来源的新事实。
- 落盘为 `chapters/NNN.md`；顺手更新 state.json（人物现状、伏笔进展、时间线），让后续章节保持一致。
- 每章完成后向用户简短汇报：写了什么、推进/回收了哪些伏笔、有无待决策点。用户随时可插入指令，指令优先级最高。
- 不必一次跑完全书。用户说继续时，读一下工作区文件即可接着写——没有需要恢复的流程状态。

## 阅读器（viewer）

用户大多不想读 JSON。**阶段 2 完成后自动生成一次**，此后每写完一章顺手重新生成一次，并提醒用户刷新页面。

阅读器是**纯静态单文件**：project / blueprint / outline / state 与全部正文都内嵌在 `<工作区>/viewer.html` 里，双击即可离线打开——**不起服务器、不联网、无外部依赖**。代价是数据不会自己更新：写了新章节必须重新生成一次，再让用户刷新页面。右上角徽标显示数据来源（正常为 `快照`；把模板直接复制使用时为 `数据文件`）。

### 生成后要告知用户怎么打开

不要只丢一句「已生成 viewer.html」。把这两件事讲清楚：

- **打开**：双击 `<工作区>\viewer.html`（或用浏览器直接打开该文件）。
- **更新**：写了新章节后重新运行一次生成器，**再刷新浏览器页面**——单纯刷新不会带来新数据。

若生成时用户正开着这个页面，明确提醒他刷新。

生成方式（按顺序尝试，先命中先用）：

1. **有 Python** —— 主路径：`python <技能>/scripts/build_viewer.py <工作区>`（加 `--open` 顺便用浏览器打开）。
2. **没有 Python** —— 先探测再决定，别直接放弃：`python -c "print(1)"`、`py -3 -c "print(1)"`（Windows 上 `python` 可能是打开应用商店的占位程序，**必须真跑一句**，不能只看 `--version`）；WorkBuddy 环境另有自带托管解释器可直接用其绝对路径。都不行则退到 PowerShell 版（Windows 自带）：
   `powershell -File <技能>/scripts/build_viewer.ps1 -Dir <工作区> -Open`
3. **两者都没有** —— 把 `viewer_template.html` 原样复制为 `<工作区>/viewer.html`，再自己写一个 `<工作区>/viewer-data.js`，内容为 `window.NOVEL_DATA = { ...同 build_viewer.py 的 payload 形状... };`。模板会自动加载同目录数据文件（`file://` 下浏览器只拦 fetch，允许加载同目录脚本）。这是最后手段，24 章全量正文逐字写出开销较大。

页面含概览 / 章节 / 蓝图 / 路线 / 状态五个视图，明暗主题，章节大纲侧栏、全书搜索、字号行距调节；蓝图与路线里出现的稳定 ID 会自动解析成可读名称。产出为 `<工作区>/viewer.html`。

纯标准库、零外部依赖、**只读**——不修改任何工作区数据文件。用户说不需要就跳过，不影响创作流程。

> 改动 payload 结构时，`build_viewer.py` 与 `build_viewer.ps1` 必须同步修改；`.ps1` 若含中文**必须存为带 BOM 的 UTF-8**，否则 Windows PowerShell 5.1 会按 ANSI 解析导致语法错误。

## 资源

- `references/schemas.md` — blueprint / outline 契约、字段限制与生成要点。阶段 1、2 必读。
- `references/writing-guide.md` — 写作与审阅的静态规则：约束优先级、一致性要求、审阅清单、修订原则。阶段 3 写作时参考。
- `scripts/novel_tools.py` — `init` 与 `validate` 两个子命令，纯标准库，可选使用。
- `scripts/build_viewer.py` + `scripts/build_viewer.ps1` — 生成本地 HTML 阅读器（五视图、明暗主题、全文搜索）。二选一，纯标准库。
- `scripts/viewer_template.html` — 阅读器模板（CSS/JS 全内联，含数据占位符）。生成器必需，也可单独复制出去手工填数据。
